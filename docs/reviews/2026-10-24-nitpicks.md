> Owner-requested sweep for every small thing, on top of the 2026-10-23/24 reviews in this folder. Nothing here repeats those docs unless it's still live. Checks were scripted greps and live `curl`s run on 2026-10-24. Each item names the file:line or URL that shows it. Only the items marked as checked live were run against production.

## Findings

Reviewed `master` @ 1ee2116 (0.2.7, Electron 44).
- **`en_US.toml:210`, the error shown when a download fails, tells players to "temporarily turn off your antivirus software".** That's bad security advice from an official launcher. It also refers to "LaunchWrapper", a Forge/legacy file a Fabric 26.3 pack never downloads, and asks players to tell "us" their antivirus so "we'll contact them". Rewrite it as "A game file failed to download or was blocked. Retry, and if your antivirus quarantined it, restore it and add an exception for the Romanica folder", with a link to Discord support.
- `en_US.toml:183`: the Java-required message links to `github.com/dscalzi/HeliosLauncher/wiki/...`, which is upstream's wiki, not ours. Point it at a romanica.net help page.
- `en_US.toml:66`: "+ Add Mojang Account". Mojang accounts were retired years ago, and the pass-2 review recommends deleting the whole Mojang path. Until then, at least hide the button.
- Old-org URLs players can click: `_custom.toml:7,14,15` (media, source and support links), `en_US.toml:210` (issue link), `settings.js:1536` (release notes feed) and `uicore.js:40` (mac DMG). Plus `package.json` `repository`/`homepage`/`author`, and `dev-app-update.yml` (`owner: Imperium-MC`, `repo: ImperiumLauncher`). All work by redirect today. Change them to `Romanica-MC/RomanicaLauncher`, and point support at Discord rather than GitHub issues, since players don't have GitHub accounts.
- `package.json` `name: imperiumlauncher`. The data dir is `%APPDATA%/.imperiumlauncher` (configmanager.js:14), next to Electron's `userData` (`Romanica Launcher`). Two app-data roots with two names. Keep the old one, since moving it costs players their installs, but document why.
- `electron-builder.yml:13`: the "ROMANICA CUTOVER: repo URLs flip when the GitHub org renames" comment is done and stale. Delete it.
- 26 `console.log` calls in app code. One of them (authmanager.js:145) prints the Mojang session (pass-2 review). Route the rest through `LoggerUtil`.
- Four Helios-era TODOs (processbuilder.js:514,781, settings.js:398 "Dont know what these errors are. Just show them I guess.", uicore.js:97).
- jQuery is used at 68 `$(` sites in renderer scripts, which is the whole reason the 87.5 KB vendor bundle ships.
- Only `en_US.toml` exists, but the website ships de/es/pt. If the launcher stays English-only, say so on the download page.

## Cross-repo inconsistencies

- **Two vote-site lists.** The website has 9 sites (`romanica-frontend/src/lib/site.ts:26-34`); the plugin has 8 plus 34 (`vote-sites.yml`), and most of the 34 are placeholders. Keep one list, in the backend or the plugin config, and have the other read it.
- **Game version.** The plugin `api-version` is 26.2, and the pack and plugin config say `26.2`. The launcher and client ship 26.3, and the website FAQ meta says "1.8–26.2". Settle one statement of "server runs X, client Y, joinable from Z" and use it everywhere.
- **Social handles** are `@PlayImperiumMC` / `r/ImperiumMC` on the website (`site.ts:11-17`, `llms.txt:147-149`). This is the owner's call: rename the accounts, or keep them and note it.
- **"ImperiumMC" in player-visible strings:** Discord changelog footers (backend), the pack menu description (pack), mod-menu source/issue links (client), and launcher support links. Each is listed in its repo's doc.
- **Protocol-locked old names that must NOT be renamed one-sided:** Redis keys `ImperiumMC:*`, permission nodes `imperiummc.*`, mod id and channels `imperiumclient:*`, env var `IMPERIUMMC_HMAC_SECRET`. Rename them only in a coordinated change across both sides.

## Pass 2 (agent)

Reviewed `master` @ 9ade898 (0.2.7). Scope: `app/**`, `index.js`, `scripts/**`, the lang toml files, `launcher.css` and `distribution/distribution.json`, plus the smoke driver because PR evidence depends on it. Checks were greps, a lang-key and DOM-id cross-reference script, and live `curl`s run on 2026-10-24. Items already listed in pass 1 aren't repeated. Items fixed by the open PRs from this run (#16, #18, #19) are tagged.

### Evidence and CI

- **The launch smoke has not proven an in-game boot on master or for 0.2.7.** `test/smoke/launch-smoke.cjs:363-367` passes on `[SMOKE] game spawned` plus "no failure markers", even when `latest.log` never appears. The runs for master (40057431406), the `v0.2.7` tag (40057990821) and this run's PR branch (40069070915) all end on that fallback verdict, and their `launch-smoke-logs` artifacts hold only `launcher-stdout.log`/`launcher-stderr.log`. With no `latest.log` after a 20-minute watch, the JVM likely never logged anything. That is the 0.2.6 failure mode AGENTS.md calls a fail. Make the fallback a FAIL when `latest.log` is absent, and re-run before trusting 0.2.7.

### Error messages that send players to the wrong place

- `en_US.toml:158,181,196,199,212`: "See console (CTRL + Shift + i) for more details." The launch pipeline now runs in the main process (`app/main/launchservice.js`, 10 call sites use these strings), and nothing forwards main-process logs to the renderer. DevTools only shows renderer logs, so the details players are sent to look for aren't there. Point them at the log file or at Discord instead.
- `en_US.toml:312` (`fatalErrorMessage`): "could not be established to our servers". The index is served from `raw.githubusercontent.com` (`distromanager.js:7`), so a GitHub outage reads as a Romanica outage. That's minor, but the wording should be "the update server".
- `en_US.toml:220` (`unknownCause`): "the full report is on the clipboard button below". There's no clipboard button; the button is "Copy Report" (`:222`).
- `en_US.toml:307` (`notConfiguredMessage`) says "Microsoft sign-in will work in a later build". `AZURE_CLIENT_ID` is set (`ipcconstants.js:3`) and the regex makes `AZURE_CLIENT_ID_CONFIGURED` true, so this branch is dead copy that would be wrong if it ever showed.

### Settings that do nothing

- **Shaderpacks** (`settings.ejs:159-170`, `en_US.toml:83`). `setEnabledShaderpack` writes OptiFine's `optionsshaders.txt` (`dropinmodutil.js:14,210`), but the pack ships neither OptiFine nor Iris (`distribution.json`, 9 FabricMods, no shader loader). Choosing a pack has no effect in game. Hide the section or ship Iris (Iris reads `config/iris.properties`).
- `en_US.toml:90` (`memoryDesc`): "The recommended minimum RAM is 3 gigabytes". The distro says `ram.minimum: 2048`, `recommended: 4096` (`distribution.json` `javaOptions.ram`). Interpolate the distro values instead.
- `landing.ejs:180` + `landing.js:942-943,967`: every news article shows "0 Comments" linking to `<link>#comments`. `romanica.net/news.rss` has no `slash:comments` (0 matches, checked live) and the site has no comments anchor. Remove the link.
- `landing.js:939`: news dates render with `hour`/`minute`, but every feed item is stamped `12:00:00 GMT` (live feed). Players see a fake local time such as "5:00 AM". Drop the time fields.

### Bugs found in passing

- `landing.js:185`: `Lang.queryJS('landing.noSelection')`. The key is `landing.selectedServer.noSelection` (`en_US.toml:165`), so the server button is blank when no server is selected.
- **All external social buttons are dead.** `newsSanitize.js:28-33` allows only `romanica.net`, `github.com`, `docs.oracle.com` and `minecraft.net`. Main re-checks with the same list (`index.js:131-137`), so the landing Discord, X, Instagram and YouTube icons (`_custom.toml:8-11`) are all rejected. Discord is fixed in #19. X, Instagram and YouTube wait on the owner's handle decision (the `@PlayImperiumMC` handles).
- `index.js:46-58`: the `autoUpdater.on(...)` listeners are registered inside `initAutoUpdater`, which the renderer calls on every page load (`uibinder.js:61`). A renderer reload doubles every update notification.
- Two lang tables are never read: `[js.settings.mstfLogin]`/`[js.settings.mstfLogout]` (`en_US.toml:244-252`, a typo of `msft`; the code reads `settings.msftLogin`). `js.landing.downloadJava.findJdkFailure` (`:188`) is also unused.

### Corrections to earlier passes

- Pass 2 #6 (`os.release` used as a value): **not a live bug.** Node's `os.release` has a `Symbol.toPrimitive` that returns the release string (`String(os.release) === '10.0.26200'` on the agent machine), so the regex matched correctly. #16 makes the call explicit and pins it with a test that passes both before and after.
- Pass 2 #4 (`toggleDropinMod` renames the mods dir): the rename is `rename(<file>, <modsDir>)`, which fails (EPERM/EISDIR) instead of moving the folder. The real damage: a name with `.disabled` mid-name loses everything after it, and a double disable appends `.disabled.disabled`. Fixed in #16.
- Pass 3 #4 also cites `uibinder.js:206` `accounts[0]`. That branch only runs when exactly one account is left, so it's correct.
