# Code Review: RomanicaLauncher (2026-10-23)

> **Repo:** Romanica-MC/RomanicaLauncher · **Reviewed commit:** `355b68d` (master) · **Method:** static review of working tree at HEAD
> Severities: **P0** = broken now · **P1** = likely bug / security hole · **P2** = design debt · **P3** = nice-to-have

## Project Snapshot

Romanica Launcher is the official Minecraft launcher for the Romanica server — a hard fork of Helios Launcher (MIT) rebranded and re-architected for the Romanica pack. Stack: Electron 39 + Node 22, with `helios-core` 2.3 doing the heavy lifting (distro model, Mojang/Fabric index processing, JDK management, Microsoft auth); the fork's own work is a main-process core (`index.js`, `app/main/*`), a sandboxed renderer with a strict IPC bridge, and a re-implemented asset pipeline with stronger integrity checks. Roughly 8k lines of first-party JS plus 11 test files (74 tests, all passing; eslint clean). Very active: ~20 commits in the last 5 days (Oct 18–23), version 0.2.6, with daily distro bumps and a live Windows smoke pipeline.

## Architecture Assessment

The architecture is a deliberate three-layer split and it is executed consistently:

- **Main process owns everything dangerous.** `index.js` + `app/main/{launchercore,launchservice,ipc,crashreport,redact,userdatamigration,smokelaunch}.js` handle config, distribution loading, the launch pipeline, auth, crash uploads, and the auto-updater. The renderer (`app/assets/js/scripts/*`) is plain browser JS.
- **Renderer is locked down.** `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` (index.js:281-286); strict CSP (app/app.ejs:3: `script-src 'self'`, `connect-src 'self' https://romanica.net https://github.com`, no `object-src`); `will-navigate` blocked, `setWindowOpenHandler` denies all child windows, and external links are re-validated main-side against an https host allowlist (`index.js:303-319`, `newsSanitize.isAllowedLink`).
- **The IPC surface is a named-operation bridge, not a passthrough.** `app/preload.js` exposes a fixed allowlist over `ipcRenderer.invoke`; `app/main/ipc.js` validates every handler's arguments (bounded strings, path containment via `pathContained`/`ownedRoots`, allowlisted `ConfigManager` mutations in `CONFIG_OPS`, dialog property filtering). `test/preload-bridge.test.js` asserts the preload exposes exactly the allowlisted keys, so bridge drift fails a test.
- **Downloads run in a forked child** (`assetdl.js` forked via `ImperiumRepair.spawnReceiver`), validating against the locally cached index and downloading with a 15-wide worker pool, per-artifact retry/backoff, and mandatory hash verification. The distribution index ships per-artifact MD5 + sha256 (`distribution/distribution.json`), generated by `scripts/generate-distro.cjs` (Modrinth/Fabric resolved, downloaded once, hashed) and re-verified nightly by `scripts/validate-distro.cjs` (ranged-read zip central directory, fabric.mod.json dependency checking, Jar-in-Jar inspection).
- **Java is spawned via an args array** (`processbuilder.js:85` `child_process.spawn(javaExec, args, ...)`), so there is no shell-metacharacter surface; natives are extracted synchronously before spawn, with the smoke-mode guard verifying `lwjgl.dll` lands in the folder `-Djava.library.path` actually names (the issue #4/#5 lesson, enforced in `_verifySmokeNatives`).

Weak spots are concentrated in Helios-inherited code that was ported rather than redesigned (`processbuilder.js`, `configmanager.js`), in the legacy Mojang auth path, and in CI coverage of the test suite itself.

## Strengths

- **Download integrity exceeds upstream.** `assetdl.js:333-381` verifies *every* completed download against the distro hash regardless of received size (upstream Helios skips verification when sizes match), prefers sha256 over MD5 (`pickVerification`, lines 173-179), deletes a failed file before retrying (`await fs.remove(asset.path)`, line 373), and refuses to write any path containing an `undefined` maven segment (`assertNoUndefinedPaths`, lines 119-129) — the issue #14 regression is defended at three layers including tests.
- **Renderer-compromise containment is real, not cosmetic.** Every renderer-initiated mutation is validated main-side: `TRASH_ITEM` restricted to launcher data roots (index.js:101-126), `OPEN_EXTERNAL` re-checked against the same allowlist as the renderer (index.js:131-150), `OPEN_PATH` requires a directory inside owned roots (ipc.js:304-321), `CONFIG_APPLY` is an explicit op table with per-op validators (ipc.js:139-227). News/RSS content goes through DOMPurify with a strict tag/attr allowlist plus a hook that strips non-allowlisted href/src, and fails closed if DOMPurify can't load (newsSanitize.js:126-150); server listings are built entirely through the DOM API (renderutil.js).
- **Crash-report privacy is well-engineered.** `redact.js` implements a versioned, mirrored-with-backend rule set (Windows profile paths, POSIX homes, env refs, Bearer/labelled secrets/JWTs), applied at the source (crashscreen.js:252-259) *and* as the last gate before the POST (crashreport.js:114-127), with UTF-8-boundary-safe truncation, a 10s abort timeout, and explicit 429/413 mapping. Pure functions throughout, backed by `test/redact.test.js` and `test/crashreport.test.js`.
- **Verification culture is unusually good.** `smoke.yml` boots the real game on a Windows runner with pinned+checksummed Temurin and Mesa, uploads logs; `ci.yml` nightly re-validates every distro URL with full hashing ≤25 MiB and `--full` in CI; AGENTS.md codifies "evidence from a real run," tests-must-be-able-to-fail, and "never launch the game on the agent machine."
- **Careful destructive operations.** `managedmodcleanup.js` only reaps files provably launcher-owned (provenance manifest + helios maven-layout adoption regex, lines 64-91), unions referenced paths across *all* servers before deleting, and never lets cleanup fail a launch (launchservice.js:382-392).
- **Small things done right:** `userdatamigration.js` copies (never moves) the legacy profile and is fully injectable/tested; `crashreport.js`'s `truncateToBytes` handles multibyte cut points correctly; the Microsoft auth window watches for the exact nativeclient redirect prefix and the login reply carries only the query map (index.js:195-209).

## Issues

- **[P1] Transient auth failure at startup silently deletes the stored account.** `validateSelectedMojangAccount` (app/assets/js/authmanager.js:327-352) falls off the end and returns `undefined` whenever `MojangRestAPI.validate` reports a non-SUCCESS status (network error, 5xx); the same happens on a throw via the `catch(_err)` in the `AUTH_VALIDATE_SELECTED` handler (app/main/ipc.js:445-461). Either way `valid` is falsy and the handler runs `ConfigManager.removeAuthAccount(selected.uuid)` + `ConfigManager.save()` — one flaky request during the startup validation logs the player out. The re-add-on-cancel path in uibinder.js:171-187 paper over it for users who notice, but the account and its client token are gone from config. (The Microsoft path is intentionally different — a genuinely unrefreshable account should be removed — so the fix is to distinguish "validation failed" from "token invalid".)
- **[P2] No CI workflow runs the tests or the linter.** `ci.yml` only validates the distribution index, `smoke.yml` is dispatch/tag-only, `build.yml` only builds installers. The 74 tests and eslint (verified passing locally today) can regress silently on any PR; given AGENTS.md's own standard ("a CI step that runs zero tests must fail, not go green"), the suite isn't currently enforced anywhere.
- **[P2] `build.yml` can publish a release before the smoke gate runs.** It grants `permissions: contents: write` (lines 9-10) and passes `GH_TOKEN` to `npm run dist` (lines 34-37) on every push to every branch. electron-builder's CI default publishes on tags, so pushing a `v*` tag makes Build publish while `smoke.yml` (same tag trigger) runs in parallel — the release lands without the "release only after smoke passes" rule from AGENTS.md. Restrict this workflow to a plain build on branch pushes (no token, no write permission) and keep publishing to a tag-gated job that *waits for* smoke.
- **[P2] Pre-1.19 native extraction has a zip-slip hole.** `processbuilder.js:829` does `path.join(extractDir, fileName)` with raw zip entry names and no `..` guard (the 1.19+ branch at lines 878-884 is safe — basename only). Inactive for the current pack (MC 26.3 takes the 1.19+ path) and inputs are hash-verified Mojang artifacts, but it's inherited unguarded path traversal one branch flip away from live; also `fileName.indexOf(exclusion)` is substring matching, so an exclusion like `.git` can over-match.
- **[P2] Auth tokens are mirrored wholesale into the renderer.** `launchercore.configSnapshot()` (app/main/launchercore.js:243) serializes the entire `authenticationDatabase` — MC access token, Microsoft access token, and the long-lived MS *refresh* token — into `window.imperium.env` via the synchronous bootstrap. File-level plaintext storage is normal for MC launchers, but the mirror duplicates the crown jewels into renderer memory where any renderer compromise (the XSS surface exists: RSS HTML) reads them directly. The UI only needs `uuid`/`displayName`/`type`; keep tokens main-side.
- **[P3] `setJavaExecutable` accepts any string and later gets spawned.** ipc.js:164-167 validates only length (≤1024) and processbuilder.js:85 executes it. No injection (args array, no shell), but a compromised renderer could point the exec at an arbitrary binary as the pivot from XSS to code execution. Cheap hardening: require an existing file named `java`/`javaw` at validate time (`JAVA_VALIDATE` already runs `validateSelectedJvm` on it — the *stored* value just isn't re-checked at spawn).
- **[P3] `MODS_ADD` moves files from any absolute source path.** ipc.js:526-555 validates `srcPaths` only as absolute; main then `fs.moveSync`s them into the instance mods/shaderpacks dirs. Legitimate for drag-and-drop (`webUtils.getPathForFile`), but it means renderer compromise can relocate arbitrary user files into the game directory.
- **[P3] Dead code in mod-library resolution.** `processbuilder.js:932` tests `mods.sub_modules != null` on an Array — always falsy — so libraries declared by enabled Forge/Lite mods are never merged from that loop (inherited from upstream Helios; loader-declared libraries still arrive via `_resolveModuleLibraries`).
- **[P3] `getSelectedServer(def=true)` returns the wrong default.** `configmanager.js:288` returns `DEFAULT_CONFIG.clientToken` instead of `DEFAULT_CONFIG.selectedServer` (copy-paste; both are `null` today, so it's latent, not live).
- **[P3] Unescaped regex interpolation of the player name.** `launchservice.js:414` builds `new RegExp(...${authUser.displayName}...)`; current MC names are `[A-Za-z0-9_]{3,16}` so it can't throw today, but escape it (or use `indexOf`) since the value comes from the profile API.
- **[P3] Windows path-containment checks are case-sensitive.** `pathContained` (ipc.js:95-104) and the trash handler (index.js:112) compare `startsWith` on resolved paths without case-folding; a differently-cased equivalent path (only craftable by a compromised renderer, since legit paths are main-generated) slips the guard on win32.
- **[P3] Unawaited `Imperium.launch()` calls in the renderer.** landing.js:375 (download-failure "Retry All") and landing.js:455 (after Java scan) fire the promise without await/catch; pipeline failures still surface via `failure` events, but the rejection itself is unhandled noise.
- **[P3] Legacy Mojang auth is still fully wired** (login UI, `authmanager.js` Mojang branches, config shapes) years after account migration — dead surface that carries the [P1] and a pile of error-mapping code; consider deleting it.

## Testing & Tooling

74 `node:test` tests pass and eslint is clean (CRLF enforced via `eslint.config.mjs`). The suite is behavior-focused, not coverage-theater: `assetdl-verification.test.js` proves same-size corruption is rejected, `distro-cleanup.test.js` proves player files are never reaped, `preload-bridge.test.js` pins the bridge surface *and* the CSP string, `smoke-driver.test.js` regression-tests the "previous run's log" trap from AGENTS.md, and tests stub `APPDATA` so they can't touch real user data. Gaps: nothing in CI executes the suite (see [P2] above); `app/main/ipc.js` validation logic (`CONFIG_OPS` validators, `pathContained`) is untested despite being pure and security-bearing; `authmanager.js` has zero tests; the monthly `dependency-watch.yml` (npm audit + OSV) is the only vulnerability gate. Packaging (`electron-builder.yml`) is clean — asar on, sensible file exclusions, GitHub publish config — but installers are unsigned, so both SmartScreen and the electron-updater chain rest entirely on GitHub TLS + repo integrity.

## Top Recommendations

1. **Add a CI job that runs `npm test` + `npx eslint app test scripts` on every push/PR.** Cheapest possible win; it would have caught the [P1] class immediately.
2. **Fix account removal on transient validation failure** (authmanager.js:327-352 + ipc.js:445-461): only remove an account when validation *definitively* failed; on network errors return a distinct "unknown" state and keep the account.
3. **Tame `build.yml`:** drop `contents: write` and `GH_TOKEN` from branch builds; make tag publishes depend on the smoke workflow passing (needs/smoke gate), matching AGENTS.md's own release rule.
4. **Keep tokens out of the renderer mirror:** strip `authenticationDatabase` tokens from `configSnapshot()`/`bootstrap()`, expose `uuid`/`displayName`/`type`, and resolve the avatar/launch data main-side.
5. **Harden the two filesystem edges:** add a `..`/absolute-segment guard to the pre-1.19 native extraction (processbuilder.js:829), and case-fold roots before `startsWith` in `pathContained`/trash-item on win32.
6. **Code-sign the Windows installer** (even a cheap OV cert removes SmartScreen friction and gives electron-updater a real integrity anchor), and plan to move `REMOTE_DISTRO_URL` (distromanager.js:7) off `raw.githubusercontent.com` onto `api.romanica.net` — you already run that host for crash reports, and it centralizes the supply chain you're defending with all those hashes.
